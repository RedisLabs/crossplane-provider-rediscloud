# Keep served API files during generation

Date: 31 October 2026.
Status: Accepted.
Owner: Shay Berman.
Acceptance: generation must leave both served versions on disk.
Design: this file.
ADR: none. Storage stays the version already chosen for the managed kinds.
BDR: none.

## TLDR

`make generate` keeps `zz_*` files under `v1beta1` and `v1alpha1`, and it
installs `goimports` before the Upjet generator runs. The Terraform provider
pin stays 2.19.2.

## Problem

The cleanup step deleted every `zz_*` file outside `v1alpha1`. That removed
the storage version, `v1beta1`, including `zz_generated.deepcopy.go`.
`go generate` lists package files before the directives run. The Upjet
generator then stopped because `goimports` was not on `PATH`, so
controller-gen never rewrote the deepcopy file. The next package failed
opening it.

## Behavior

The cleanup keeps `zz_*` files under `v1alpha1` and `v1beta1`. Controller
files and examples are still regenerated. `generate.init` installs
`goimports` from `golang.org/x/tools` v0.51.0, the version already required
by this module, into the host tools directory and puts that directory on
`PATH`.

`v1beta1` is storage for the 27 managed kinds. `v1alpha1` stays served while
a cluster CRD `status.storedVersions` still lists it. Lookups stay
`v1alpha1`. ProviderConfig stays `v1beta1`.

## Non-goals

A Terraform provider bump. A Terraform CLI bump. A Crossplane, Go, or Upjet
bump. Dropping served `v1alpha1`.

## Validation

`scripts/test_alignment_guards.py` checks that the cleanup excludes both
served versions. `make generate` exits 0 with `TERRAFORM_PROVIDER_VERSION`
still 2.19.2, and a second run leaves the tree unchanged.
