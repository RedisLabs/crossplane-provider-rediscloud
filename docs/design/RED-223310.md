# Pro database passwordless attribute

Date: 31 October 2026.
Status: Accepted.
Owner: Shay Berman.
Acceptance: Shay asked for Terraform alignment on 2026-10-30.
Design: this file.
ADR: none. The Terraform attribute already chooses the wire.
BDR: none.

## TLDR

`spec.forProvider.enablePasswordless` is the generated field for Terraform
`enable_passwordless` on `rediscloud_subscription_database`. True asks that
provider to write an empty password. Omitting the field leaves both
`enable_passwordless` and `password` out of the Terraform parameters.

## Problem

The Pro database managed resource has to match the pinned Terraform provider.
That provider has had `enable_passwordless` since 2.13.0. The pinned schema is
2.19.2. The attribute is an optional bool. The schema snapshot carries no
default value, and the provider sets the default to false, so an omitted
config value does not write an empty password. Generation already emitted the
field. This note records that contract so a later change does not replace it
with a Cloud API boolean.

## Behavior

The spec field is `enablePasswordless` on `spec.forProvider` and
`spec.initProvider`. The JSON name is `enablePasswordless`. The Terraform name
is `enable_passwordless`. Both served versions, `v1beta1` and `v1alpha1`, keep
the field. `v1beta1` is storage.

A nil field is omitted. `GetParameters` then has no `enable_passwordless` key
and no `password` key. A password secret reference does not turn the attribute
on and does not put `password` in that map. The Terraform schema default is
false, and that provider writes an empty password only when the attribute is
true.

Explicit true puts `enable_passwordless: true` in the parameters and still
puts no `password` key there. The empty-password write stays inside the
Terraform provider.

Explicit false puts `enable_passwordless: false` in the parameters and puts
no `password` key there.

Late-init skips an observed false, including when state also has a password
string. The spec field stays nil. Late-init copies an observed true. That
adoption still does not add a `password` key.

`password` remains `passwordSecretRef`.

## Non-goals

A Cloud API boolean. A Terraform provider bump. A Terraform CLI bump. A live
subscription or database. Active-Active `globalEnablePasswordless`, which is
already generated.

## Validation

`config/database_passwordless_test.go` covers the pinned schema, both served
types, omission, explicit true, explicit false, and late-init. No cluster and
no Cloud API call.
